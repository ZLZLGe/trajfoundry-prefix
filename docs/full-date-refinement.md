# 完整日期的脱敏增量去重与标准化发布

完整输入先通过 `submit_cluster.py --check-only --extra-information messages_only` 生成普通消息前缀基线。`scripts/submit_refinement.py` 接受同一 `--input-plan`、成功的 `--baseline`、固定 SHA256 的 `--source-manifest-ref`，将全部输入的最终决策写到共享目录；该入口只读 S3。

## 比较和核验

先重新检查基线保留集合，要求普通前缀新增删除为零。之后在完整保留集合上使用 `placeholder-relaxed-v1`，沿用已有身份边界、消息投影、工具 ID 绑定与代表排序。候选索引选择最有区分度的消息结构／无标记哈希条件；较短消息序列仍保留候选资格。这个优化与逐对必要条件筛选的结果相同，不设邻居数量或轨迹抽样上限。

候选索引还利用占位符不能跨 CR／LF 的既有规则：换行序列必须相同，作为模式一侧不含占位符的行必须与另一侧对应行一致。因此，普通提示词中的大写格式标签不会使正文已明显不同的请求进入大量无效读取。行哈希仅用于提前排除不可能关系，所有保留下来的候选仍由完整文本比较器核验；此优化不增加或减少允许的匹配关系。

两阶段决策关联只生成待验证关系。每条被删除的原始轨迹必须通过独立原始 JSON 比较器，直接匹配最终保留文件；失败的直接关系恢复为保留。全部最终保留文件重新读取，再次运行普通前缀及脱敏比较，二者都为零新增合并后才产生成功回执。若恢复轨迹后出现新的覆盖关系，任务失败并保留现场，不能发布未稳定的集合。

`refined/` 包含全量 `decisions/`、直接关系 `audit/`、`retained-input/`、普通与脱敏复跑证据、脱敏增量 `explanations/` 和汇总 `report.json`。汇总区分基线减少量、脱敏增量及直接关系恢复量。推理字段仅从比较投影排除；仅含推理的 assistant 回合仍占据位置。原始轨迹不改写。

## 发布

发布配置使用 `publish_selection=false` 和 `comparison_mode=placeholder-relaxed-v1`；输入仍是原标准化版本的完整清单。发布器核对全部证据文件摘要和每条最终对应关系，再在 Cluster 中重新读取源文件并验证哈希、保留轨迹格式、派生指标和删除依据。

百万级决策、检查结果及复制回执采用 Driver 本地临时磁盘上的 SQLite 索引，读取共享目录的冻结 Spark 分区文件，不将整套结果收集到 Driver。索引可重建，核验证据与阶段回执持续保存在共享目录。lineage 下载与上传采用流式文件传输，按最终代表合并且保持原始来源集合。轨迹原名、原字节复制到新版本，完整读取目标并核验 SHA256，最后写入原标准化契约的 manifest。

普通前缀发布及标准化与指标筛选同时发布的已有行为保持兼容。业务阶段统一由 Spark Cluster 执行；失败目录保留，只有同一发布配置拥有且内容一致的对象可用于续跑。
