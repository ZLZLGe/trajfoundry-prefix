实际差异包括 Boyue 的关键词变化、用户活动变化、会话时间、当前日期与星期、工作目录、指令条数及 system/developer 角色变化。5 对只差特定环境信息行，其中 4 对为日期与星期，1 对为 CWD；这些内容仍可能影响任务语境，因此保留原比较边界。该检查不穷尽所有不同长度、不同开头的潜在前缀。

## 本轮发现并修复的边界

两组 TokenPlan 代表对的动态 `cch` 在第 6 行：前面先有 Claude Code 身份说明，经过空行后才出现完整计费行。原规则只处理消息开头的计费 header，漏掉了这种结构。

新增 `claude_preamble_cch`：仅识别 Claude Code 身份说明首段后紧接的完整 `cc_version=…; cc_entrypoint=…; cch=…;` 计费行，只屏蔽 cch 值。身份说明、模型、版本、入口和真正指令继续精确比较；用户文本、任意内部行、代码围栏和后续引用示例不适用。独立原始 JSON 比较器也验证这些边界。

该规则以独立策略项记录，旧四条规则的决策不能直接作为新策略复用。全量重比实际新增 4 条，其中还包括代表对检查以外的较短前缀。保留文件仍是原 JSON，不把归一化后的比较投影写回轨迹。规则详见 [rules.md](rules.md)。

大 `_sub_N` 编号也已核对：TokenPlan 2026-10-12 的 `session-fdb53999-a5c9-4dd9-87bc-f0c14bddf454` 家族由 2,717 条降到 56 条。逐个读取这 56 个输出并校验哈希，发现属于同一比较组，但有 12 种首个 user 消息，消息数为 20–998，assistant 消息数为 6–406。大编号既可能包含旧匹配遗漏，也可能包含不同任务；输出沿用原文件名，不重新编号。

## 代码和执行

主比较使用 `2b69c72`；按两位哈希分目录写出及四规则独立核验使用 `8176c0c`；新增计费标记规则及完整增量验证使用 `c541c1e`。各作业使用独立源码快照；首次写出与三项四规则核验的源码哈希完全一致。新规则单独提交并推送。

自动化测试 **86 项通过**，静态检查通过。主任务 32 个 Executor × 8 核；独立核验 16 × 8；完整复查、开头检查、规则增量比较各 8 × 8；全部新增覆盖关系的复现与独立核验各 4 × 8。业务运行使用 Spark 3.5.7 Cluster 和用户队列。

千万级运行同时验证了两个性能修复：隔离保留的脱敏记录按文件引用分散，避免共同前缀造成单分区倾斜；实际文件按两位哈希分目录，减少共享目录竞争。完整复查只写决策，最终清单引用已验证的原文件，避免重复复制整套数据。这些性能处理不改变分组、工具定义约束或轨迹内容。

真实 session 可在本轮选定日期之间比较；无 session 的记录仍按日期隔离。`sub_session_id`、旧分片编号和文件名里的 `_sub_N` 不拆开比较组。额外信息只约束工具定义；消息里的实际指令、正文、参数和结果仍比较。分组和边界见 [grouping.md](grouping.md)。

当前最终清单用于本项目重跑与后续数据接入；旧分类调度使用的 manifest／lineage 协议仍需单独适配。
