# 分组与 `_sub_N` 的含义

新项目仍先分组，再比较消息前缀。同组只代表候选范围，不代表组内轨迹会全部合并。

| 情况 | 比较范围 |
|---|---|
| 有真实 `session_id` | 渠道／数据集 + model + harness + user_id + end_user_id + session_id；已选输入中的同会话可跨日期比较 |
| 没有 `session_id` | 渠道／数据集 + model + harness + user_id + end_user_id + 日期；旧 sessionless 分片号不阻断比较 |
| 同时没有 session 和用户身份 | 仍限同渠道、模型、harness 和日期，并要求至少 6 条原始消息、1,024 个内容字符和工具结果 |

比较时，先按当前四条规则生成仅用于比较的消息序列，再检查短序列的每一条消息是否等于长序列对应位置的消息。短序列整体被覆盖，并且短轨迹的工具定义都包含在长轨迹中，才删除短文件。例如 `[A, B]` 可由 `[A, B, C]` 覆盖，`[A, X]` 不能由 `[A, B, C]` 覆盖。工具调用 ID 可以一致更名，但工具名、参数、结果和调用／结果绑定仍需一致。

`sub_session_id`、`sessionless_chunk_id` 和文件名里的 `_sub_N` 不参与分组。同一 session 的 `_sub_9` 可以被 `_sub_1000` 覆盖；不同问题、不同工具参数或结果产生的真实分支仍保留。

Spark 按范围和前两条比较消息的哈希分区，再按完整比较序列排序，用磁盘 SQLite 保存候选和最终对应关系。相同前缀始终进入相同分区；没有把整个大组收集到 Driver 内存。哈希只选候选，最终用实际比较内容证明覆盖。

已确定因身份脱敏、工具绑定异常或匿名历史不足而隔离保留的记录，按文件引用分散到不同分区。它们始终保留，也不能作为删除其他记录的依据，因此分散处理只改善负载，不改变任何可合并组或去重条件。2026-10-10 至 10-12 全量实测发现一个慢分区集中 12,432 条身份脱敏记录后增加了这一处理。

## 为什么会有很大的编号

已核对现有 Spark 标准化代码：它对一个标准化 scope 中仍保留的真实 session 根轨迹，按 `created_at`、标识及来源排序后从 0 编号，再写入 `sub_session_id`。这个编号不是轮数，也不是经过人工确认的业务分支数。严格匹配留下的回放差异、真实内容分支，以及复用同一个 session 标识的独立请求，都可能增加编号。

本次固定样本最大编号：Boyue 73、DeepInfra 852、FreeRouter 14,566、TokenPlan 830、SXF 603。下面是对完整文件名家族逐个读取所得的结果；“首个 user 消息”按原文本精确统计，不推断它是否为用户真正的第一个业务问题。

| 渠道／日期／文件名家族 | 文件数 | 不同首个 user 消息 | 实际比较组数 | 消息数范围 | 有工具调用的文件 |
|---|---:|---:|---:|---:|---:|
| FreeRouter / 2026-10-15 / intern-discovery | 14,567 | 14,354 | 1 | 3–3 | 0 |
| DeepInfra / 2026-09-21 / f97b2e93-0839-4713-9399-c231f1525c07 | 853 | 851 | 1 | 3–3 | 0 |

FreeRouter 最大编号案例里的大多数用户问题本身不同，不能只看共同的 session 标识就合并。TokenPlan 这个家族还含 3 个模型，按用户、模型等字段形成 4 个比较组。SXF 的例子具有大量共同历史，但能否合并仍取决于后续消息和工具定义，而不是编号接近与否。

| 家族 | 原始条数 | 保留 | 合并 |
|---|---:|---:|---:|
| FreeRouter / intern-discovery | 14,567 | 14,567 | 0 |
| DeepInfra / f97b2e93… | 853 | 853 | 0 |
| TokenPlan / 641df26d… | 831 | 100 | 731 |
| SXF / 019f6f10… | 604 | 569 | 35 |

TokenPlan 这个案例合并了 87.97%，确有大量可覆盖的分支；FreeRouter 和 DeepInfra 两个三消息家族没有满足当前完整消息覆盖规则的重复项。上述四个家族在 `preserve_all` 和 `tools_only` 下的保留数量相同，这次放宽额外信息带来的 976 条额外合并来自其他家族，不能把两种收益混为一谈。

新项目复制原文件，保留原文件名和 `sub_session_id`，不重新编号。去重后编号允许不连续；最终条数看 `manifest.json` 的 `trajectory_count`。实际减少多少见 [本次验证报告](validation-20261117.md)。
