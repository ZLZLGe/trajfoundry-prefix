# 比较规则与边界

所有规则只作用于临时比较投影，落盘轨迹保持所选输入文件的全部字节。不向轨迹添加字段。核验日志是独立产物。

## 基础规则

- 同渠道／数据集、模型、harness 和身份范围内比较。真实 session 之间不合并；缺失 session 的记录按用户和日期比较，已有分片号不阻断内容覆盖。
- 匿名且缺失 session 的记录需至少 6 条原始消息、1,024 个可见内容字符和工具结果，才参与同日内容去重。此时只能证明内容覆盖，不能反推原始 session。
- 每条消息的角色、正文、调用顺序与内容保持精确比较。沿用原标准化前缀投影，排除响应与历史回放不稳定的 reasoning 字段。
- 默认 `extra_information=tools_only`：短轨迹的工具定义必须全部包含于长轨迹，定义中的参数 schema 等也要匹配。按用户确认的分类用途，其他附加信息不阻止合并，包括子 agent、压缩项、媒体映射、服务端调用附录、agent_messages、来源扩展、顶层 instructions 和未知顶层字段。消息里的 system/developer 指令、正文、工具参数与结果继续比较。
- 用 `--extra-information preserve_all` 可以复现之前的保守策略：额外资产需要包含，子 agent、压缩项和未知扩展字段要求相同。两种策略都完整复制最终保留文件，不把比较投影写回轨迹。
- SHA256 仅用于排序候选；删除前比较真实投影字节。每条删除记录再次向最终保留文件验证，不能指向已经删除的中间文件。

## 1. Claude billing header 的 cch

已在真实 TokenPlan 原始请求中确认，同一调用继续回放时，system 首行 cch 改变，其他指令一致。cch 是动态计费标记，不改变分类所需的用户任务。

只屏蔽 system/developer 或 instructions 开头 `x-anthropic-billing-header:` 那一行的十六进制 `cch=...;` 值；版本、其他字段、真正指令和用户文本继续精确比较。不会在任意文本里做替换。

## 2. assistant 正文末尾的 ASCII 空白

真实采集出现 response 的正文为两个换行，下一次 request 回传同一工具调用时省去了空白正文。只在 assistant 比较副本里去掉末尾空格、制表符、CR 和 LF；正文内部、开头、Unicode 空白、user/system/tool 内容、工具参数均不动。本条规则不删除消息；完全空的 assistant 由第四条单独判断。

## 3. 工具调用 ID 一致更名

真实 TokenPlan 记录已确认响应 `chatcmpl-tool-...` 在后续请求变为 `call_...`，调用名和原始参数逐字节相同。ID 是引用标识，更名本身不改变任务内容。

在比较副本中按调用出现位置分配编号；对应 tool 结果映射到该编号。保留调用数量、顺序、工具名、参数与结果全文。不同结果绑定到不同调用时不会合并，即使两个调用的工具名和参数完全相同。重复调用 ID、孤立结果、名称绑定冲突会隔离保留。输出仍使用原文件中的原始 ID。

原始采集已见到 `chatcmpl-tool-b3cb45593ef254c6` → `call_9dff2e35e5da25c7` 的 Read 调用更名，标准化保留了这两个不同 ID；新比较规则可以识别这种前缀。不能据此推断是客户端还是网关改写的。

另一个 exec_command 案例虽然更名后的消息前缀一致，但较长文件缺少短文件中的 53 项工具定义。因此两种策略均保留两条。消息前缀相同是必要条件，工具定义也必须被覆盖。

## 4. 回放省略完全空的 assistant

跨渠道大样本的保留结果里发现，已有正常 assistant 正文或工具调用之后，一条记录包含完全空的 assistant，后续记录回放历史时没有这条消息。例如共同历史 H 后，短记录是 `H → assistant(全空)`，长记录是 `H → user(继续) → assistant(...)`。原先按消息位置比较会被这个空信封阻断。

只在比较序列中略过这样的消息：

- 前面已经出现过有正文或工具调用的 assistant，起始空回复不动。
- 正文为空；ASCII 尾部空白只有同时启用第二条规则才可视为空。
- 没有工具调用，推理正文、推理详情和 reasoning 字段均为空。
- 原消息没有媒体、名称、扩展字段等其他载荷；即使未知字段的值是 null，也保留整条消息。

只有推理而没有正文的 assistant 不属于本条规则的空消息。工具调用、用户消息、系统／developer 指令、工具结果一律不能因此跳过。原消息计数仍用于匿名记录的准入门槛，输出保留原文件，`total_rounds` 和原 `messages` 不改写。

该规则只能处理无内容的回放差异。非空 assistant 正文后来被省略、工具结果被摘要或截断、脱敏内容前后不一致，都继续保留为不同记录，不能当作空消息处理。

## 5. Claude 身份说明首段之后的 cch

10 月 10–12 日全量结果的开头指令检查发现两组 TokenPlan 候选：system 内容先包含 Claude Code 身份说明，经过一个空行后才出现完整计费行。该行的动态 `cch` 不在消息第一个字符处，第一条规则无法识别。

新增独立规则 `claude_preamble_cch`，只处理以下结构：消息从 `You are Claude Code, Anthropic's official CLI for Claude.` 开始，首个非空段落结束后，紧接 `x-anthropic-billing-header: cc_version=…; cc_entrypoint=…; cch=十六进制值;` 完整一行。身份说明段内出现代码围栏或另一个计费 header 时不应用本规则。

只屏蔽这一行的 cch 值，身份说明、模型名、版本、入口、后续真实指令仍逐字比较；不会扫描任意内部行，不忽略用户消息或后续引用示例。本规则独立列入策略，因此旧四条规则的决策不能被当作新策略直接复用。独立原始 JSON 比较器也核对相同边界，输出文件字节保持不变。
